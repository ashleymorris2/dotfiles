# dotfiles

Managed with [chezmoi](https://www.chezmoi.io). The source lives in `~/.local/share/chezmoi` and chezmoi writes real files (not symlinks) into `~`.

## New machine

```sh
# 1. Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. Pull and apply dotfiles
sh -c "$(curl -fsLS get.chezmoi.io)" -- init --apply <github-username>

# 3. Install tools
brew bundle --file="$(chezmoi source-path)/Brewfile"
```

## Day to day

| Task | Command |
| --- | --- |
| Edit a managed file | `chezmoi edit --apply ~/.zshrc` |
| Pulled in edits made directly to a file | `chezmoi re-add ~/.zshrc` |
| Start managing a new file | `chezmoi add ~/path/to/file` |
| See what would change | `chezmoi diff` |
| Apply source to home | `chezmoi apply` |
| Commit and push | `chezmoi cd`, then `git add -A && git commit -m "..." && git push`, then `exit` |

Editing `~/.zshrc` directly and forgetting to `re-add` means the change isn't tracked, and the next `chezmoi apply` will overwrite it.

## What's in here

| Source | Deployed to | Notes |
| --- | --- | --- |
| `dot_zshrc` | `~/.zshrc` | Shell config, aliases (incl. `obk`) |
| `dot_wezterm.lua` | `~/.wezterm.lua` | Terminal config |
| `dot_config/ohmyposh/` | `~/.config/ohmyposh/` | Prompt theme |
| `dot_config/shell/functions` | `~/.config/shell/functions` | Shell helpers, sourced by `.zshrc` |
| `dot_local/bin/` | `~/.local/bin/` | Personal scripts |
| `dot_taskfiles/restic/` | `~/.taskfiles/restic/` | Obsidian backup Taskfile (see below) |
| `.chezmoiexternal.toml` | `~/.oh-my-zsh/` | Pulls oh-my-zsh and plugins from GitHub |

### Externals

oh-my-zsh and its plugins aren't committed here. `.chezmoiexternal.toml` tells chezmoi to download them from GitHub on `apply` and refresh weekly. That's why `chezmoi managed` lists thousands of files while the repo stays small. Use `chezmoi managed --exclude=externals` to see only what's actually tracked.

### Ignored paths (`.chezmoiignore`)

Patterns are target paths relative to `~`, not source names.

| Pattern | Why |
| --- | --- |
| `README.md`, `Brewfile`, `scripts/` | Repo-only. Kept in git, not copied into `~` |
| `.oh-my-zsh/cache/**` | Regenerated by oh-my-zsh. Without this, `chezmoi apply` stops to ask about changed cache files |

`.gitignore` is separate: it controls what git tracks (e.g. `.DS_Store`), not what chezmoi deploys.

## Obsidian backups

Restic snapshots the vault into a local repo, then rclone pushes it to Proton Drive (folder set to online-only).

```
Vault -> restic -> ~/Backups/obsidian-restic -> rclone -> Proton Drive
```

| Command | Does |
| --- | --- |
| `obk` | Snapshot, prune, push to Proton |
| `obk --list` | All tasks with descriptions |
| `obk --summary <task>` | Full explanation of a task |
| `obk verify` | Check the Proton copy matches local |
| `obk restore TARGET=~/Desktop/restored` | Restore latest snapshot |
| `obk doctor` | Sanity-check paths, tools, repo and remote |
| `obk pull` | New machine: download the repo from Proton |

Secrets are never stored here. The restic and rclone config passwords live in 1Password (`restic-obsidian`, `rclone-config`) and are fetched with `op read`. rclone's Proton login lives in its own encrypted config and needs setting up per machine with `rclone config`.

# Tools

## rsync_helper
`rsync_helper` is a simple script that wraps rsync allowing a source and remote to be pre-configured in a local file for ease of use.

### Usage
The script expects an .env file to define remote connection details.

Create the .env file at:

```bash
mkdir -p ~/.config/rsync
[nvim/vim/nano] ~/.config/rsync/.env
```

Add the following environment variables (customizse as needed):


```ini
RSYNC_REMOTE_USER=user
RSYNC_REMOTE_HOST=yourserver.com
RSYNC_REMOTE_DIR=/var/www/main_project
RSYNC_LOCAL_DIR=$HOME/project
```

Then to sync changes to the remote it's as simple as running:

```bash
rsync_helper push
```
Optionally it can be called with the standard rsync flags, e.g.:

```bash
rsync_helper push --dry-run --exclude="*.log"
```
